# 唐代东亚战略地图｜潼关原型设计文档 v0.1

版本：0.1（设计草案）  
日期：2026-10-14  
原型标识：`tongguan_slice_v01`  
关联文档：`01_系统设计文档_v0.1.md`

> 本文描述拟制作的原型和验收条件。实际 DEM、河湖与地点资料尚未取得，本文不提供虚构的潼关坐标、精确唐代城墙尺寸或已通过的测试成绩。原型同时测试地图美术工艺和工程闭环，不是历史复原的认证。

## 1. 原型目标

制作一块能体现“山河限制通行、关隘控制要道”的潼关区域。在固定方向的同一世界中，从东亚粗略总览连续缩放到关城近景；能选择关隘、看到军队沿受控通道移动、在预留空地建设、切换扩张与损毁，保存重读后保持一致。

工坊端可以人工修改一条道路、冻结关城、删除一簇树林，再只重生成未锁定区域。地图生成前后，关城、道路、删除意图和通行规则必须保持约定不变。

不是以一张精美图片作为完成条件。真正的交付物应包含：可运行场景、可编辑源文档、版本化素材、生成配方、人工补丁、运行时地图包和验收报告。

## 2. 历史范围与证据边界

用户确认“唐朝时期”，但未确认具体开局年份。本原型先命名为“唐代潼关地理意象原型”，`scenario_year` 暂为空，不能直接作为已考证的历史剧本发布。

公开资料提到天授二年（691）潼关迁建的情况。因此不能把所有唐代阶段都默认成同一关址，更不能直接把今天的景区城墙当作唐代布局。黄河水利委员会网站相关文章和人民网关于旧潼关的报道可作为历史线索，但不足以确定每段墙、每个渡口的位置。[H1][H2]

本版采纳的设计约束为：河流与高地压缩主要陆路；关城位于可控制的交通节点；关后有适量驻军与补给用地。具体城形、营房与预留地块属于游戏设计，不标注成出土或史料复原。

原型正式制作前需要一页“历史选择说明”：选择的时代范围、采用的关址、定位依据、现代地理需修正的部分、已知不确定项。年份未定不阻塞工程占位，但阻塞“历史准确”验收。

## 3. 两级范围，保持同一世界

### 3.1 地理背景区

范围应能看清主要河道、南侧高地与沟谷、向关中和东侧方向延伸的道路。初始数据裁切可试约 24×16 km 或按实际输入调整；这是采样工作区建议，不是潼关历史城池尺寸。

地理事实进入范围后再决定构图，不为塞进固定画幅随意截断关键通道。东亚总览用低细节底图和少量测试地点，不要求此时完成全图美术与全部历史边界。

### 3.2 关城展示区

关城及紧邻道路、坡岸、仓储、居民组团以近景显示比例制作。可用约 4096×3072 制作单位作为初始工作画布，拆成若干缓存块；制作单位不是米，不等同原 DEM 像素，也不要求它占满整个地理背景区。

数据适配负责地理定位与展示夸张。关城接路、河岸和山地约束必须随映射保持正确；无法同时满足时降低夸张程度或扩大展示工作区。

### 3.3 对照相机

至少固定四个相机书签：东亚总览、关中东侧区域、潼关地理背景、关城近景。每次构建记录同一组位置、缩放和显示开关，便于对比，不通过随意换镜头掩盖接缝。

## 4. 画面构图与地理约束

不要从“先造一座城，再围着城随机放山河”开始。先识别或人工标注河岸、高地边缘、主要通道和防线位置，再生成建筑。

| 区域 | 画面职责 | 生成约束 |
|---|---|---|
| 主河与岸线 | 提供连续边界和交通背景 | 建筑不得跨入水域；不自动生成主河桥梁 |
| 山地、塬坡与沟谷 | 显示可展开空间被压缩 | 关键沟口、陡坡和通行边界人工确认 |
| 主要陆路 | 让玩家看清关隘为何重要 | 必须接关门和外部道路接口；不可被树或新街区堵住 |
| 关城核心 | 成为视觉与控制焦点 | 关门、主防线与街区锚点固定 |
| 关后用地 | 容纳驻军、粮仓和少量生活设施 | 可留建设空地，但不侵入主通道 |
| 关外节点 | 少量聚落、岗哨、补给点 | 密度低，不扩成与主城争夺焦点的第二座大城 |
| 水运附属点 | 需要时提供渡口／码头外观 | 只有逻辑资料授权时才新增渡河或水运连接 |

基于实际方向表达“北侧黄河、南侧高地”的关系；屏幕上的左右前后服从固定世界映射，不为了复制参考图的构图把地理反转。局部防线不必机械做成笔直横墙，以通过地形和连通性验收为准。

## 5. 战略逻辑场景

### 5.1 主通道

设置关前、关后两个测试端点及被潼关控制的道路边。关隘允许通行时普通军队可通过，关闭时该主要陆路边不可通过。

这是对选定测试走廊的判定，不表示整个东亚从此绝对不存在其他远距离迂回路线。测试报告必须明确检查范围与已启用的其他路线。

### 5.2 山路与渡河

第一版不新发明历史密道。现有仓库已有“轻装单位、险径已知、普通军队禁行”的测试语义，可保留为合成测试场景，不宣称其对应一条已考证的潼关历史小径。[R1]

河面默认不能被普通陆军穿过。确需渡河，使用独立 `crossing` 或主游戏对应逻辑边，并记录方向、条件和与关隘控制的关系。码头贴图和船只装饰均不能自动产生通行许可。

### 5.3 状态和显隐

关楼图片损毁不自动决定开关。主游戏提供关隘控制状态；表现系统读取状态显示破坏或封锁。缩远、关闭城池美术层或隐藏树木不能改变通行判断。

仓库路径诊断明确不是战役移动权威，应继续作为编辑器验证工具。运行时路径和存档由游戏系统负责，原型只建立适配与一致性检查。[R2]

## 6. 关城布局与预留建设

### 6.1 布局骨架

首版固定主关门、防线接点、关内主路、至少一处仓储区、至少一处驻军区与外部道路接口。街区可以在既定用地内变化，但不能通过随机种子搬动关门和核心走廊。

优先采用街区或院落组团，减少独立单屋组合的接口问题。具备单栋表现的设施只保留少量高辨识目标。

### 6.2 建议的 8 个建设槽位

这些地块是游戏设计占位，不是历史建筑清单。它们可按布局实际条件移除或合并，数量不用强行凑齐。

| 稳定 ID 后缀 | 可选设施 | 空地和道路要求 |
|---|---|---|
| `rear_storage_01` | 粮仓／仓库 | 接关内后勤道路，不占据关门前通道 |
| `rear_military_01` | 营房／训练场 | 关后平整用地，必须可接路 |
| `rear_workshop_01` | 工坊／维修设施 | 与后勤区邻接，预留装饰占地 |
| `civil_01` | 民居组团／商铺 | 靠生活支路，不挤占军事主路 |
| `civil_02` | 市集／客舍 | 近关后节点，不把关城变成均匀满铺 |
| `defense_01` | 瞭望设施／加固设施 | 只能沿已审核防线或高地点设置 |
| `expansion_01` | 外围仓储组团 | 阶段解锁，不移动原有街区 |
| `expansion_02` | 附属营地／民居 | 在预留外围用地中增长 |

原则上仓储、民居、营房用地不能互相无限替代。建筑类别由地块的 `allowed_buildings` 控制，特定防御点需要更窄的允许清单。

### 6.3 留白的两种含义

可建设空地保存地块 ID、面积、建设条件和道路接点。永久留白包括主路、关前集结通道、河岸缓冲与陡坡：它们看上去可能空着，但不能让建设自动填满。

初始可建设余量建议占城内可开发用地的 20%–30%，以组合画面调节。坡地和水面不算可开发用地。

### 6.4 城市变化

最低实现三档成长和独立损毁：简约、常态、强化；每档都可叠加完好、局部受损、严重受损。

原型不要求绘制九张整城图。三档主要控制模块显隐和预留街区启用；损毁作用于墙体、关楼和建筑组团变体。

建设流程为：选择潼关 → 选择空地 → 选择允许设施 → 显示在建或已建模块 → 更新游戏存档。拆除后地块恢复空置或废墟状态，仍沿用原 ID。

受损时不得整体随机布局。修复后相同街区、相同城门和玩家建筑回到原位。主关楼、墙段和重要设施优先制作专属损毁变体；背景民居可先用少量组团废墟替代。

## 7. 高度图驱动的生成配方

### 7.1 人工输入最小集

实际 DEM 裁切及元数据；已校准河岸／水域；关隘锚点；主通道折线及出入口；需保持的高地／沟谷边界；关城允许范围；建筑禁入区；建设地块；相机书签。

原型开始时允许人工标注关键山脊和关口，不要求先实现一个能自动发现全国所有关隘的算法。

### 7.2 自动内容

依据坡度与人工地形约束生成坡面表现；沿已给定河岸生成岸线带和局部笔触；在可耕地候选区布置少量田地；在非禁入区域布置林簇；在审核后的关城模板里选取街区变体和初始占用。

程序必须输出“因为什么没能放置”：坡度过大、与手工内容重叠、没有道路连接、进入水域等。不能为了满足对象数量而强行放入不合法位置。

## 8. 首批美术资产

### 8.1 先做组合小样，不先批量出图

最小视觉测试只需一段坡岸、一片水、一组树、一段墙和一座关楼。认可的是合成后的画面：地形连贯、接地、线粗、尺度和视角一致，而非分别认可几张独立 AI 图片。

沿用用户第一张中国城池参考的建筑方向；城堡成长长图只参考成长节奏；空地形图用于观察连续坡地、留白、道路和树林关系。

### 8.2 初始预算

下表为制作预算建议，不是必须精确完成的数量。方向变体属于实际独立资产，不能假装旋转同一张图即可解决。

| 类别 | 初始预算 | 说明 |
|---|---:|---|
| 城门／关楼 | 2–3 | 主关楼和简化／受损表现 |
| 城墙组件 | 6–10 | 选定方向直段、连接、端部、转折和破损 |
| 功能院落与建筑组团 | 8–12 | 营房、仓储、官署意象、民居、市集 |
| 损毁组团 | 3–5 | 与主要占地、锚点匹配 |
| 林簇和灌木 | 5–8 | 稀密、坡地、岸边，严格限制变形 |
| 岩石、坡脚、岸边细节 | 5–8 | 作为连续地形的补充，不代替整个地形 |
| 田地和生活细节 | 3–5 | 少量田块、围栏或货物等 |
| 地块提示与选择反馈 | 2–3 | 建设预览和选中态，不烘入地形 |

合计约 34–54 件组件；可先做其中 12–16 件完成第一轮视觉试验。地表底色、水面和坡面合成尽量由程序或通用纹理完成。

### 8.3 每件资产需验收

透明背景与边缘扩色、固定视角、统一光向、统一线粗、合理屏幕尺寸、接地点、地面占地、连接点、允许朝向、损毁配对与风格版本。墙体至少进行一次连续连接试验，院落至少放进一组街区后再判断可用。

具有明显方向的斜俯视建筑，默认禁止任意旋转和无条件镜像。AI 素材中的草地、水面或投影背景应分离，避免合成时重叠出两套地面和两套阴影。

## 9. 四档显示与接口

全局档只显示潼关标记、名称优先级和相关战略地理；区域档显示关隘轮廓与主路；地方档显示城防、土地与周边地形；近景档显示功能院落、建设空地和受损模块。

锚点、道路接点和点击返回的 `site_id` 始终相同。关隘未加载详细素材时显示代理，不能无法选择。

地形缓存的渐变和建筑代理转换分别调节，避免黑线重影。相机书签之外还要测试临界缩放缓慢来回滚动，不能只用快速跳转检查。

军队使用共享逻辑路线的视觉折线。若路线经过前景树或城门，采用明确的前后层或通过预定显示带，避免军队穿过屋顶。原型不承担真实攻城动画或城内逐街寻路。

## 10. 手工保护试验

先生成一版地图，并保存其构建号。人工移动一个仓库、改一段道路、删一簇树、冻结关城与一个建设地块。

随后对关城外树林进行三类操作：改变随机种子、改变密度、更新部分资产。每次都展示差异预览，再提交。人工内容及其依赖必须保持稳定；允许变化的只有明确选择且未受保护的区域。

额外测试：把一个对象移过块边界、删除跨块对象、修改穿过锁区的河岸候选、生成器版本升级造成 ID 失配。结果应是保留或明确报冲突，不是静默覆盖。

保护层与玩家状态分离：冻结一个地块的制作几何，不妨碍玩家在其内建设；玩家建了仓库，不反过来改写工坊原始布局。

## 11. 验收矩阵

测试应保存输入版本、输出版本、操作记录和截图或数值报告。“建议目标”达不到时应报告真实结果，而不是删除失败用例。

| 编号 | 场景 | 合格条件 |
|---|---|---|
| GEO-01 | 隐藏建筑，看地形和道路 | 作者能看出通道收束位置，关隘锚点符合已审核约束 |
| GEO-02 | 检查建筑与河岸／高地 | 无未经批准的入水、穿山、堵主路；必要例外有记录 |
| GEO-03 | 核对历史版本 | 剧本年份、关址和不确定项明确；未定则历史验收标记待定 |
| NAV-01 | 主关开放，普通军队由关前到关后 | 指定主走廊连通，并返回对应逻辑控制边 |
| NAV-02 | 主关关闭 | 指定主走廊不可通行；不把局部结果夸成全图无路 |
| NAV-03 | 军队直接跨主河 | 无显式过河逻辑边时不可通过 |
| NAV-04 | 合成轻装险径用例 | 仅满足已知／单位条件时开放，普通军队不可借用 |
| NAV-05 | 隐藏建筑、植被或切换 LOD | 上述通行结果不变 |
| LOD-01 | 东亚总览连续缩到关城再返回 | 无场景跳转、黑块、明显位置突变，地点 ID 不变 |
| LOD-02 | 临界倍率慢速来回 20 次 | 无持续闪烁，名称不重叠失控，资源不反复抖动加载 |
| LOD-03 | 大坐标区域近景平移 | 固定测试下锚点误差目标小于 1 屏幕像素，无可见抖动 |
| ART-01 | 坡岸、道路、树林组合 | 无显著方块拼缝、漂浮贴纸、两套光向或透视 |
| ART-02 | 选定近景构图 | 作者明确认可，不能由程序日志代替美术认可 |
| BUILD-01 | 在允许地块建设仓库 | 新模块落在正确占地，不堵主路，接路有效 |
| BUILD-02 | 切换成长档 | 新增模块在预留区出现，旧地块和建筑 ID 不搬家 |
| BUILD-03 | 损毁后修复 | 对应模块原位切换，成长与损毁状态彼此独立 |
| SAVE-01 | 建设、损毁后保存重读 | 地块、成长、损毁与主游戏权威状态一致 |
| REGEN-01 | 改种子／密度 | 锁定对象与人工道路保持规范化数据哈希不变 |
| REGEN-02 | 人工删除后重新生成 | 被删对象不恢复、不换 ID 绕过删除记录 |
| REGEN-03 | 新候选侵入人工区 | 报冲突或拒绝，不静默挤开人工内容 |
| REGEN-04 | 生成中断、撤销、重开 | 恢复完整旧版或完整新版，不留半张地图 |
| CHUNK-01 | 穿越区块边界 | 河岸、道路不断裂，无重复城楼／树簇、无明显色缝 |
| PERF-01 | 固定发布构建 60 秒视角轨迹 | 报告 p95／p99、峰值内存显存、冷／热加载；与约定预算比对 |

## 12. 开发顺序及退出条件

**P0：隔离与保全。** 记录现有版本，运行旧文档与通行测试，建立只读样本和独立工作区。不把旧素材或地图改写为新格式后才开始测试。

**P1：灰盒全尺度验证。** 用粗东亚底图和潼关占位节点验证同一相机、锚点、拾取和四档显示。这里无需成套美术，但必须测最远景。

**P2：地形和素材工艺验证。** 做小范围坡岸、树林、关楼组合；比较逐个节点、分块烘焙等方案的画面和开销。未获认可就暂停新增素材类别。

**P3：地理骨架与模板。** 导入实际数据、核对关址阶段、确认主路、防线和可建设用地。人工约束应在生成配方里可追溯。

**P4：城市状态与人工保护。** 完成 8 个左右地块、成长、损毁、保存重读、局部重生成和删除记录。代码更改尽量一次解决一项验收，不一次重写整个插件。

**P5：运行时发布与压力。** 导出不依赖工坊的节点包；在实际 PC 的发布构建下测试，并形成完整验收矩阵。

只在地理、美术、保护和性能均达到约定标准后，新增第二个不同类型节点。第二个节点优先验证不同地理条件，而不是简单复制同一河岸关城换名字。
