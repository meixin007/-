## 0. 本版决定什么

### 0.1 一句话目标

**让潼关的一小块地图真正接近参考图，并把现有单节点显示改造成只加载当前需要区域的地图系统；不在本阶段制作全东亚。**

本版最终交付两个相互配合的结果：一个可在 Godot 中连续缩放、建设与损毁的手绘组合样板；一个在同一世界、同一相机下实际执行加载、卸载、回退和预算控制的多区域验证场景。

程序功能、美术效果和规模能力分别验收。不能用数百项逻辑测试代替作者对画面的认可，也不能用一张漂亮截图证明资源可以流式加载。

### 0.2 本版必须完成与不做的事

| 必须完成 | 明确不做 |
|---|---|
| 固定画风、视角、接地与素材接口的小样 | 不批量制作所有唐代建筑或全国美术 |
| 连续坡岸、树林、道路、关楼与院落的组合 | 不把完整 AI 插画当成无法编辑的最终节点 |
| 同址成长、原位损毁与已有地块的表现替换 | 不增加经济、军粮、战斗、自由摆房等玩法 |
| 版本化美术包和由制作结果生成的地图包 | 不改 Save22、v4 地图和原战役权威的含义 |
| 可见对象索引、按需加载和真正的释放 | 不启动时加载所有详细地图，也不重建全图对象计划 |
| 单世界合成多区域压力、故障与往返测试 | 不把显示副本数换算成已支持的历史城市数 |
| 少量测试势力区域与远景地名显示 | 不编造唐代全东亚边界、人口与地名资料 |

**新增第二个真实历史城市／关隘不是本版必交项。** 多区域验证用明确标注的工程夹具；新增真实节点需等本版视觉和流式加载关卡通过后另行立项。

### 0.3 原则不变

固定方向，仅平移和缩放；一套稳定地理坐标与地点身份；重点地区精细、普通地区概括；现代高度资料负责地形骨架；关键山河关系不得为了装饰被破坏；制作期生成，人工修改后发布；玩家状态不由美术决定。

## 1. 已有基线与本次修复的处理

### 1.1 已确认的起点

PR #1 已合并。仓库报告记录：完整占地检查、树木边缘剔除和跨块唯一性三个审查项已有红绿回归；原生制作 163 项、运行 58 项、树木边缘 86 项通过。此处引用的是仓库的修复构建证据，不是本文编制时独立运行的结果。[S01][S02]

修复后的完整占地算法采用有限线段与矩形的距离检查，旧规则的相切和容差语义有明确记录。新 `instance_index.gd` 提供 ID 校验、派生 owner、跨块 membership 与提交审计，且不修改原始对象和存档。[S03][S04]

### 1.2 不再作为“待修复”重做

REV-01／02／03 进入永久回归集。v0.2 只在新素材、新索引或新绘制路径影响这些行为时扩充用例，不重写一套相互矛盾的检查器。

已有 grandfather／旧内容豁免处理只适用于**相同旧对象与相同规则版本下的已记录内容**。对象移动、换成更大素材、改变占地或修改保护规则后，不能继续借用旧豁免。新冲突先报告，不自动删树、搬楼或扩大通道。[S02]

### 1.3 目前仍缺什么

| 基线事实 | v0.2 的动作 |
|---|---|
| 地形仍是六块单节点常驻缓存 | 引入资源生命周期、需求集合、预算和淘汰 |
| `_draw()` 仍对全部树调用 `Instances.plan()` | 改为数据修订时建索引、镜头变化时查可见候选 |
| 原生报告测试了界面重建，但保留 Session 缓存 | 增加不同区域的真实释放、重载和失效测试 |
| 院落、短墙、损毁及地形笔触仍含工程占位 | 建立最小成套美术及组合审阅，而非堆更多代码屋顶 |
| 已有关址语境与现代资料，精确复原未完成 | 保留来源与不确定项，不在本版自动补桥或宣称复原 |

以上分别依据修复报告、活动绘制器与美术缺口说明。[S02][S05][S07]

### 1.4 基线性能不能被误读

修复报告的 60／300 秒轨迹 p95 分别为 9.596／9.345 ms；16 个纯显示副本 p95 为 60.792 ms，仍超预算。实际普通窗口客户端为 1886×1061，并非精确 1920×1080。该报告已经分别记录执行成功和预算结果。[S02]

本版不因上述成绩承诺全国容量，也不把旧构建不同分辨率的结果与新构建直接比较为“提速百分比”。先固定实际渲染尺寸再进行 A/B。

## 2. 交付范围与规模夹具

### 2.1 V：真实视觉样板

仍以已有潼关数据、关楼、地块和受控通道为基础。工作区沿用现有 24×16 km 地理背景；不要求整个工作区达到参考图密度。重点美术范围由实际河岸、关楼、支路与地块分布选定，至少跨越两个相邻的详细地形页。[S06]

第一轮制作约 **12—16 个可组合资产／部件变体**，而不是 12—16 张整城插画。认可后才补全该小样的必要损毁和方向变体。一次最多提交两条风格候选，不无限扩充风格分支。

输出必须是引擎合成结果：同一组镜头下的全景、近景、地形独显、建设前后、损毁与修复；另给连续平移缩放录像或逐帧序列。

### 2.2 E：单世界多区域工程夹具

单独使用 `stream_lab_v02` 工程 world_id，不写入真实战役。夹具与真实样板调用同一套地图显示服务，不能维护“演示专用加载器”。

| 夹具 | 内容与目的 | 不能得出的结论 |
|---|---|---|
| E-small | 4×4 个相邻细页；跨边树、道路、水岸；测试接缝与基础调度 | 不表示 16 座城市已完成 |
| E-stream | 初始约 256 个有唯一内容的分页资源，8×32 或等价拓扑；相机沿长路线访问 | 资源数不能直接等于城市容量 |
| E-query | 1千／1万／10万条装饰元数据，保持同一镜头内的可见数量一致 | 元数据规模不等于同时绘制数量 |
| E-sites | 约32个合成地点代理，其中最多4个按 LOD 进入详细表现；其余只显示代理 | 不创建32套战役、军队或完整城市模拟 |
| E-labels | 约2000个合成地名与少量相邻势力区域；测试筛选、避让与共享边界 | 不宣称历史地名、政区准确 |

夹具的最终资源数应由**唯一解码／显存估算总量至少为测试软预算的3倍**决定；256 是起点，不是绕过内存试验的固定数字。地形页须具有不同内容哈希，不能让所有页指向同一纹理，利用去重伪装卸载成功。共享建筑／树木图集允许且应共享，但单独记账。

不要求把整个夹具的详细纹理一次装入内存。可以按生成配方离线逐页构建，记录总量并沿测试路线逼出淘汰行为。

## 3. 总体系统：只新增一条表现构建与调度链

```text
原始地理与已审核约束 ──────────────────────────────────────┐
既有 v4 文档 + 人工补丁 + 删除记录 + 锁区 ── EffectiveMapAdapter ├─ 有效制作快照
版本化素材 + 风格配方 ──────────────────────────────────────┘
                             │
                    TerrainStylizer / MapPackageCompiler
                             │
       世界目录 + 稀疏地形金字塔 + 实例分片 + 地点代理 + 构建收据
                             │
                 VisibilityPlanner → ResidencyManager
                             │
             空间索引 → 可见绘制计划 → 地形 / 地物 / 地点 / UI
                             ↑
                已有 GameState / 建设 / 军队 / Save22
                      只通过既有状态适配读取
```

本版新增模块以**组合、接口与小适配器**接入现有项目，不继续叠加 `final2 → final3 → final4` 的深继承链。现有逻辑服务不为了地图显示重新实现。

### 3.1 模块契约

| 模块 | 主要输入 | 输出 | 禁止承担 |
|---|---|---|---|
| `EffectiveMapAdapter` | 已校验制作发布、原 v4、sidecar | 带稳定 ID 的有效快照、修订号 | 自动修正原数据或写玩家进度 |
| `ArtBundleValidator` | 素材清单、纹理、风格配置 | 尺寸／边缘／接点／占地报告 | 自动签署作者美术认可 |
| `TerrainStylizer` | 数值地形、山脊引导、岸线、风格 | 连续地表候选与结构笔触 | 从图片反推战略通行 |
| `MapPackageCompiler` | 有效快照与素材 | 不可变分页包、依赖和差异收据 | 改写旧地图、全图一次烘焙为巨图 |
| `ChunkSpatialIndex` | 活跃分片及完整绘制范围 | 反向桶索引、可见对象 ID | 保存世界权威状态 |
| `VisibilityPlanner` | 相机、稀疏目录、LOD规则 | 需要页／预取页／代理需求 | 读取全部高细节对象 |
| `ResidencyManager` | 需求与字节预算 | 加载、挂接、回退、淘汰 | 以 visible=false 假装释放 |
| `MapRenderer2D` | 可见计划与已驻留资源 | 分层绘制及真实提交记录 | 每帧重算全图生成结果 |
| `SettlementPresentationAdapter` | 旧地块与游戏状态 | 资产变体、显隐与建设提示 | 修改地块 ID、资源价格或军队路线 |
| `AcceptanceRecorder` | 操作、帧时、生命周期与构建身份 | 原始证据及独立验收状态 | 以总断言数掩盖失败或未执行项 |

模块名和入口为本版拟定，不表示仓库当前已经存在。

## 4. 坐标与形状契约

### 4.1 保留当前定位，不做镜头投影重构

已有地理元数据采用 Albers 投影，局部 x 向东、y 向南；显示方向是格网方向，不自动等于真北。当前数值栅格为600×400、40 m像元，来自名义30 m DSM重采样。[S06]

v0.2 沿用这一地面映射与地点锚点。斜俯视感由统一的素材、坡面结构与遮挡表达，不在缩放时把地面从俯视切到另一套投影。第一轮不把高度逐像素转换成屏幕竖向位移，也不局部扭曲河岸来塞进关楼。

大型世界值继续保留双精度标量或整数页坐标与局部数值；**先减相机／页原点，再构造送往绘制的 Vector2**。新分页不要把整块几何先转成巨大绝对浮点向量。Godot 的大世界坐标设置不会自动解决二维渲染精度。[G04]

### 4.2 分清四种形状

| 名称 | 意义与用途 |
|---|---|
| `logical_geometry` | 原有通道、地点与战略判定；由现有游戏权威管理 |
| `ground_footprint` | 建筑或树的接地占地，负责放置、地块容纳和接路 |
| `paint_bounds / paint_polygon` | 可画出的全部树冠、屋顶、阴影和装饰范围，负责视口剔除、跨块索引和烘焙邻域 |
| `protection_envelope` | 该类对象与道路／水岸／锁区的安全检查范围及规则版本；可能比接地占地大 |

“完整绘制范围不碰水”与“树根不入水”是不同规则。本版不自动放松现有林簇完整保护规则；需要树冠悬水等例外时另记对象级批准，不能换个字段绕过旧保护。

REV-01 的矩形—有限线段检查继续用于其适用的矩形包络。复杂多边形使用覆盖相交、端点与最小距离的独立验证器，不能把仅适用于矩形的算法直接称为任意多边形精确算法。

### 4.3 不混淆三种网格

**生成网格**决定默认对象身份和随机采样，旧 `forest_grid_sha256_v2` 不变。  
**实例索引网格**帮助查可见对象，旧兼容视图仍可使用512 m owner规则，属于派生数据。[S04]  
**地形纹理分页**决定图像分辨率与加载范围，可有层级，不决定城市或树的身份。

更改纹理页尺寸不能让树换 ID，也不能使人工删除记录失效。owner随显示位置重算时，只影响派生索引，不写回旧 v4 或 Save22。

## 5. 画风定标：先决定“拼起来长什么样”

### 5.1 风格配置 `tang_ink_wash_v02_candidate`

第一轮产物必须包含一份风格卡：参考画面裁切标识、固定镜头、建筑两条地面轴、屋顶方向、接地点、主光向、线条与纹理密度、土地／水／树／屋顶／墙体色样，以及1×显示尺寸。色值通过小样选定，不在代码中各自猜测。

参考图的取用范围保持原约定：中国城池图用于建筑与总体画风，空地形图用于连续坡面与留白，城堡成长长图只用于同址增建节奏。不得照搬西式尖塔与城堡形制。

风格卡一旦获认可便有独立版本。后续素材不合风格时改素材，不逐个改光向和相机来掩盖不统一。

### 5.2 第一轮最小资产

一座关楼及其已核对接点；两个允许方向的墙段与必要端部／转折；一个仓储院落、一个驻军或民居组团；两三类林簇；少量坡脚、岩石和岸边笔触。损毁优先保证一个仓库、一段墙能原位切换。

这是12—16件组件的工作量建议，允许用已有被认可资产减少新增量。方向变体按独立资产计，不把二维旋转的同一张屋顶假装成另一朝向。

### 5.3 明确停止条件

连续两轮组合仍出现明显漂浮贴纸、两套视角或依赖修图才能好看时，停止批量出图，出具一个方案选择记录：继续修二维笔触／素材规范，或另做离线2.5D地形烘焙实验。

后者**不自动成为本版实现路径**。若启用，必须额外提供坐标配准、遮挡与地面拾取方案，不能只换背景图而保留错位的城、路和军队。

### 5.4 视觉验收方法

用相同镜头对照旧工程占位、新合成小样与参考图方向。至少检查：山水连续、坡向可理解、建筑接地、道路穿门、墙体接口、统一线粗／光向、树林疏密、空地辨识、缩远后的可读性、损毁原位恢复。

作者给出 `accepted / revision_requested / rejected`，记录具体构建、素材哈希、镜头和意见。**同意进入v0.2开发、PR合并、单张素材认可，都不等于组合画面认可。** 未通过仅暂停素材扩量，允许不依赖新风格的灰盒加载工作继续。

## 6. 连续手绘地形的实现

### 6.1 地形真实分辨率与美术分辨率分开

40 m栅格可以指导河谷与坡地，但不能证明新增的1 m细节真实存在。将美术纹理提升至高分辨率，只增加表现笔触，不增加测绘精度。[S06]

保持原始数值资料和NoData、CRS、垂直单位及来源。普通PNG美术导入不承担数值高度精度保存；Godot的PNG导入精度限制见官方文档。[G05]

### 6.2 三层表现

**连续底层：** 全局一致的土地底色、坡度与坡向引导的明暗、河滩与水域遮罩。色阶在工作区／风格级确定，不对每个图块分别拉伸到最亮最暗。

**结构笔触：** 从地形分析得到山脊、坡脚、沟谷候选，再通过人工引导选择重要线。正式画面不默认显示全部等高线；调试层可以保留。笔触沿地势组织，避免规则格网节奏。

**地表细节：** 林簇、草地、石块、田地和岸边小纹理，根据场地与保护规则布置。连续坡面不能用大量相同小山贴纸代替。

初版使用离线CPU／二维绘制合成；对源输入、过滤尺度、风格参数、随机算法和输出版本留记录。不引入未经测试的GPU计算管线作为必需依赖。

### 6.3 可复现与边界一致

随机纹理由稳定世界采样位置与配方决定，不能以“当前处理的块序号”初始化后逐块重来。滤波和笔触生成读取扩展邻域；跨块山脊和河岸保留同一源feature身份。

每个输出页有唯一core区域与邻域gutter。只提交core；邻域用于过滤与采样。gutter按过滤半径、笔触尺寸与有效mip级别确定，不统一写死成“加8像素就永远无缝”。

### 6.4 分页与分辨率起点

细页起点为**1024×1024 texel core、覆盖512×512 m**；对应2 texel/m。当前最大缩放2.4 px/m下放大约1.2倍，是画面试验起点，不保证足够。需要更细笔触时在视觉关卡调整并重新估算资源预算。

只在重点小样提供细页。其他区域使用较粗层或已有背景，不为每一格东亚地图生成1024纹理。父级范围递增2倍，目录稀疏；东亚总览仍可作为单独、常驻的低细节覆盖，不必先建完整东亚四叉树。

### 6.5 mip与混合层级接缝

不能仅以独立图片的普通mipmap假定所有层级都无缝。构建时从一致的连续内容及邻域生成父级／mip；记录允许的取样级别。若深层mip超出有效gutter，则切换到有邻域支持的父页，或限制其使用，不继续缩到无依据的mip层。

相邻不同层级时保证覆盖无洞，父页在子页未就绪区域继续显示。开始用短时父子交叉淡化；地面不变形，主要难点是颜色、细节频率和采样边缘，不是三维地形裂缝。

## 7. 素材包：让剔除、占地、接口和损毁共用一份描述

### 7.1 最小字段

每件素材记录 `asset_id`、`style_id`、源纹理与图集区域、内容哈希、参考像素尺寸、像素接地点、显示尺寸、接地多边形、完整绘制范围、墙／路接点、排序层、允许方向、损毁变体及来源说明。

像素坐标统一相对于**图集截取后的区域**；裁掉透明边缘后必须同步更新接点与多边形。显示尺寸与真实地理比例分开记录，不能仅靠文件宽度决定一座关楼在地图上多大。

### 7.2 三条强约束

运行端视口剔除必须由实际绘制矩形或保守完整范围派生，延续REV-02修复，不重新引入固定100像素余量。

空间索引与烘焙依赖使用完整paint范围。地块建设校验使用ground／protection规则。为树换成高树种时，必须重建受影响的索引与依赖，不只换纹理。

完好、在建、受损、废墟保持同一对象ID及接地点。变体超出原有范围时要通过占地与保护验证，不能沿用一张较小完好图的旧包围盒。

### 7.3 新画风与旧锁区

风格迁移只生成候选素材映射，不覆盖旧纹理文件。旧地图可继续使用旧风格；新风格只在明确选定的样板工作副本中启用。

人工几何不变不代表锁区像素必然不变。风格／光照／笔触替换改变锁区像素时必须有独立视觉迁移记录。未批准区不得被全局shader或色调处理悄悄改色。

第一版优先保留整个被保护视觉子区的旧风格或整体批准该子区迁移，不做难以解释的逐像素混搭。视觉迁移批准不解除对象删除、地块和通道约束。

## 8. 地图包与兼容性

### 8.1 不提升已有权威格式版本

保留v4、Save22、已有world_id、site_id、slot_id和通道图版本。新增的是**表现包协议**，使用独立 `schema_id` 与 `schema_version: 1`；不要因为设计文档变成v0.2就把所有已有JSON版本一起改成2。

真实潼关仍采用现有世界身份；工程夹具采用独立 `stream_lab_v02`。某个地点的包版本、画风版本或纹理页编号不是该地点的身份。

### 8.2 建议文件组织

```text
builds/<build_id>/
  world.catalog.json        # 投影契约、地点代理、覆盖树根及资源页目录
  presentation.package.json # schema、源输入、逻辑兼容信息、风格及依赖哈希
  terrain/<level>/<x>_<y>/   # 稀疏地形页，core/gutter/mip说明及已导入资源
  instances/<shard>.json     # 稳定对象ID、资产映射、完整范围；按需读
  indices/<page>.json        # 空间页反向索引或编译数据
  settlements/<site>.json    # 只描述已有地块的表现，不持有经济和军队权威
  receipts/                 # 构建、完整性、视觉迁移与例外记录
```

这是新地图包目录，不是要求把原仓库移动成这种结构。本版优先在一个正常导出的PCK／部署目录内分页读资源，不以逐块挂载和卸载PCK作为资源释放机制。JSON／普通数据用FileAccess读取；Godot资源用经过导入的资源路径。非资源数据必须显式加入导出清单，并在无编辑器环境的发行包中验证。[G02]

### 8.3 包清单最少记录

源提交、build_id、world_id、投影与坐标契约、兼容的布局／通道身份、原制作输入与有效补丁哈希、生成器版本、风格版本、素材清单哈希、编译器版本、引擎与导入参数、页范围、父页、对象分片、预估内存与实际文件哈希。

哈希校验解决完整性，不等于作者签署、历史真实性或不可信代码安全。正式运行端只加载可信构建生成的数据与美术，不让任意外部 `.gd` 或场景脚本随美术导入执行。

### 8.4 双路径过渡

旧入口默认仍读旧包；新场景／开关使用新表现服务。两者共用游戏状态适配，不建立第二套经济或军队系统。

新入口不能同时初始化旧六块地形缓存与新流式缓存，否则内存和性能试验失真。视觉服务的选择必须在Session启动加载之前完成，或明确销毁旧视觉引用后再开始新模式。

旧存档先通过原有Save22校验，再由表现适配器按稳定ID读取。换画风不是存档迁移。新包声明兼容且布局、通道身份相同才能采用；不兼容时回到旧包或给出明确错误，不自动重新绑定玩家建筑。

若新表现选择需要持久化，先保存在独立v0.2测试配置中，并以world／布局／存档身份关联；不擅自向Save22新增字段。已有存档内保存的制作表现仍为有效输入，不能被最新发布包静默覆盖。

## 9. 空间索引与绘制计划

### 9.1 替换每帧全量计划

当前活动绘制路径调用 `Instances.plan(model.host.authoring.generated.values())`，新索引虽校验了owner，却仍在重绘时处理全量树。[S04][S05]

新路径为：

```text
制作发布／对象修订变化 → 更新受影响分片与索引
相机视野／LOD变化     → 查反向空间桶 → 合并候选ID → 精确paint范围剔除
候选／显示修订变化    → 生成稳定排序的绘制计划
普通绘制帧           → 重用计划，仅更新相机变换和动态状态
```

`bucket_key → object_ids` 是真正的反向索引。不能只把全量扫描搬到一个名字叫 `query()` 的函数里。

### 9.2 owner不等于可见性

每个对象有唯一逻辑／存储身份和派生owner，但paint范围可能覆盖多个桶。镜头只看到跨界树冠、未看到owner所在桶时，也必须查到这个对象，并取得其所属payload。

跨块引用只携带身份和必要范围，不复制一份可独立修改的对象。未驻留的owner payload由依赖加载取得；禁止以“owner不在当前视野”为理由丢掉可见部分。

### 9.3 排序和烘焙边界

单体地物按 `(render_plane, ground_depth, stable_id)` 排序。跨块对象的排序不能退化成“先把A块全部画完，再把B块全部画完”，否则边界前后关系会错。

稳定地面可分块烘焙；会与建筑互相遮挡的前景树冠、墙体以及可损毁模块保留独立层。已烘入底图的静态对象在相同表示下不能再画一次；清单记录 `baked_representation / dynamic_representation`。

可见候选集不变时不因每个像素的平移重新排序。对象更新、换资产导致paint范围变化、显示层变动或分片载入／移除时才失效相应计划。

### 9.4 索引修订与负坐标

索引缓存键至少包含world/build身份、有效制作修订、资产范围版本和索引参数。读取已有host时只在修订变化后取得一次必要快照，避免每帧通过getter深复制整份authoring再称为缓存。

负坐标分桶使用floor而非向零截断；边界采用一致的半开区间约定，paint包络因边缘余量多引用一个桶可以接受，但最终提交必须去重。位置以所属页／世界坐标契约转换，不把不同地点的局部[0,0]视为同一位置。

### 9.5 新唯一性验收

保留原始列表查重、key与record.id一致、owner推导及真实提交审计。新增跨页查询结果的去重与屏幕参考对比。

过渡期允许同一地物最多两个**受控表示**，记录 `(entity_id, representation_id, transition_id)`。这不是允许两块同时画同一棵树：相同表示重复提交仍必须失败，交叉淡化只有注册的旧／新配对可以存在。

## 10. LOD与可读性

### 10.1 两种LOD分开

**纹理LOD**按屏幕像素密度选择地形页分辨率。  
**语义LOD**决定城市用图标、剪影、简化街区还是详细院落。

两者共用相机，但不是一个整数硬控一切。四档是用户能理解的表现层次，不要求只有四张纹理或四级地形页。[G05]

### 10.2 初始阈值与迟滞

地点LOD的判据取“固定详细布局的参考包围盒投影宽度”，不取当前图标的固定屏幕宽度，避免切换后反过来改变自己的阈值。可先按 `<32px 图标`、`32—128px 剪影`、`128—384px 简化布局`、`>384px 详细表现` 试调；进入／退出阈值相差约15%。这些值在V1/V2小样中调整后冻结，不作为历史比例。

每个地点保持同一锚点、地块与道路接点。详细资源未到不提前消掉代理；资源就绪后约150—250ms过渡。固定方向建筑默认不用任意旋转／镜像；墙体沿已制作接点组合。

### 10.3 避免二次线稿与重复城市

地形可交叉淡化。建筑优先用同一骨架加细节，或者短时成对切换；不得让不同位置的两套黑线长时间叠加。过渡资源计入驻留预算，超预算延后过渡，不以透明叠加无上限挤占显存。

### 10.4 最远景最小功能

在现有东亚粗底图上验证地点代理、名称优先级与少量势力颜色。测试势力只使用明确的工程区域，不补全未经审核的唐代边界。

标签先空间筛选，再按选中地点／行动目标／重要性排序，最后屏幕避让。默认屏幕实际绘制上限可从64条试起；大量重叠只保留高优先项或聚合标记。选中地点有独立UI回执，不为了显示所有地名把整个屏幕塞满。

势力变化只更新区域颜色与边界显示，不重新烘焙地形。相邻测试区域共享边界来源，不分别简化后制造裂缝；更复杂的政区编辑推迟。

## 11. 按需加载状态机与故障行为

### 11.1 页面状态

```text
UNLOADED → QUEUED → LOADING → READY_CPU → ATTACHING → RESIDENT
                                     ↘ FAILED
RESIDENT → EVICT_PENDING → UNLOADED
```

`READY_CPU` 是本系统的逻辑准备阶段，不承诺Godot内部纹理仍完全未触及GPU。资源API各阶段和自定义数据解析分别计时。[G01][G02]

加载失败时显示父页／常驻底图，并产生资源级错误。不因一个细页缺失使整世界黑屏，也不将缺失细页标记为成功。

### 11.2 需求集合与优先级

优先级依次为可见区域所需基础覆盖、选中地点细节、其他可见细页、移动方向预取、缓存保温。需求由覆盖树与视野求得，不从所有详细对象逐个询问是否可见。

初版预取可见区域相邻一圈并限量；视野很大时选粗层，不把“整个东亚可见”翻译成请求全东亚最高精度纹理。细节请求只在目录实际存在且达到相应阈值时发出。

### 11.3 加载与主线程挂接

初始最多2个异步资源请求在途，每帧资源采用／挂接预算2ms。只有状态为LOADED时才调用 `load_threaded_get()`；普通JSON／索引用FileAccess及独占数据处理，工作线程不直接改活动场景树。[G01][G02][G03]

2ms是调度预算，不是单次GPU操作可被抢占的保证。一次挂接已超过预算就记录真实时长并暂停本帧后续挂接；持续超预算时减小页／图集或减少挂接单元，不用“后台加载”四个字掩盖卡顿。

### 11.4 过期请求

每个请求带world／build epoch和资源内容身份。切换包或世界后，旧请求不得挂到新场景。相机普通平移只更新需求，不每帧递增全局epoch使所有在途加载白做。

Godot所查ResourceLoader接口没有提供本设计可依赖的通用线程请求取消入口。[G02] 本版采用逻辑取消：排队未开始的移除；已开始的继续跟踪，完成后安全取回并释放无人需要的引用，不挂入视图。不能把任务从自己的字典删掉就宣布资源已取消。

同一个资源路径／哈希合并请求，多个页消费者各自计引用。过期与新需求恰好指向相同内容时，可以由当前有效消费者认领；判断仍须通过当前epoch及包兼容性，不接受陈旧的对象状态。

### 11.5 资源释放

淘汰时移除显示节点／绘制命令／帧计划引用、AtlasTexture／材质引用、完成队列引用，再释放资源表中的强引用。共享图集在最后一个消费者离开后才能释放。资源缓存按引用存活；仅从自有字典删掉键不充分。[G06]

使用CanvasItem/RID路径时，确保旧绘制命令已经清空或替换；释放请求与实际GPU内存下降分开记录。引擎、驱动及分配器可以保留内存池，不能要求每次进程RSS立即回到完全相同数字；用对象／资源引用计数、unique texture bytes、周期窗口和长趋势共同判断。

## 12. 驻留预算与降级顺序

### 12.1 建议起点

以下是本版拟定参数，必须写进测试profile并在测试前冻结：

| 项目 | 初值 | 含义 |
|---|---:|---|
| 地图纹理软预算 | 256 MiB | 含常驻底图、共享图集、地形页和过渡资源 |
| 调度准入硬预算 | 320 MiB | resident估算＋在途预留；超过则不再接纳细节请求 |
| 全进程私有内存 | 4 GiB | 沿用前阶段上限；不等同地图自身预算 |
| 实测独占GPU预算 | 1.5 GiB | 沿用前阶段范围；与纹理逻辑估算分开报告 |
| 同时详细地点 | 初始最多4个 | 其他保留代理；镜头和实际负载仍影响结果 |
| 并发加载 | 2 | 避免瞬间解码／上传峰值 |
| 单帧挂接 | 2 ms目标 | 不可抢占单操作；超时必须计入帧时 |
| 非必需资源宽限 | 约2秒 | 降低临界来回抖动；遇内存压力可提前淘汰 |
| 解码数据／待采用队列 | 初始64 MiB | 与驻留索引分开记账；不允许积压无限个已加载图片 |

实际硬预算是准入规则，不是驱动层能强制保证的显存上限。小测试profile可以降低软硬预算来强制触发淘汰，但所有结果必须标明使用了哪个profile。

### 12.2 按实际格式估算

唯一纹理只记一次，引用者共享；计算包括core、gutter、mip、纹理格式、过渡双持有和临时解码内存。1024×1024 RGBA8基础量约4MiB，完整mip链约5.33MiB，这是算术量级，不含gutter及额外副本。PNG文件大小不是显存大小。

示例：32张这种无gutter RGBA8纹理约170.7MiB。加入大图集和旧／新两层过渡后很容易超过256MiB，因此不能只限制“最多加载多少块”。

### 12.3 降级顺序

先停止预取，再淘汰远离视野且无依赖的页；然后让低优先地点退到简化表示；仍超预算则降低地形细节、保留低清覆盖。选中目标应尽量保持可操作，但没有任何目标可以无条件突破硬预算。

降级不得删地块、变通行、丢建设进度。用户看到的是暂时更概括的地图，不是另一套逻辑世界。

本版先使用可见候选＋缓存绘制计划／分块底图。只有性能剖析明确显示需要时才试MultiMeshInstance2D；它不能替代空间分组或透明排序，单实例没有独立视锥剔除。[G07]

## 13. 城市表现与状态：只换外观，不加玩法

已有八地块、成长、建设、损毁与修复流程保留。本版挑选一个仓储院落和一个驻军／民居组团完成正式视觉替换，其余可继续保留明确标注的占位，不要求全部建筑门类齐备。

新表现从已有状态得到 `site_id + slot_id + building_type + construction_state + damage_level`，映射到资产和组件开关。资产选择可以使用稳定哈希，但不得因LOD、加载顺序或进出地图重新随机布局。

卸载城市显示不停止也不推进战役日期。城市逻辑继续由已有服务管理；重进时读取当前权威状态，不从上一帧缓存恢复一份旧建设状态。

军队继续用战略旗标上层显示，不新增士兵穿门洞和真实攻城动画。若美术小样需要前景遮挡，只服务建筑与静态地物；不得让关键军队状态因为遮挡而不可见。

## 14. 局部构建、锁区与版本发布

### 14.1 有效制作快照

编译器读的是“默认生成＋人工覆盖＋删除意图＋冻结内容”合并后的结果，不直接拿默认生成层烘焙。否则手工移走的树会出现在底图里，形成肉眼看到旧树、数据里却没有的幽灵对象。

**玩家建设与损毁不进入静态地形缓存。** 不可变地表和经批准的静态装饰才允许烘焙；可变建筑、军队、势力与文字保持运行时层。

### 14.2 失效依赖

对象移动使旧paint范围和新paint范围涉及的页失效；素材变大使相关引用和保护检查失效；地表笔触修改影响其滤波邻域；局部修改还要重建受影响父页／代理。

父页未就绪时不得混用“旧父图＋新子图”假装完整发布。运行时先继续用整个旧构建；新构建依赖闭合后再整体采用。复用未变化资源可以，但必须能追溯其内容哈希。

### 14.3 原子发布与恢复

构建在新目录完成，验证清单、依赖与校验和后才切换活动指向；中断、磁盘满、文件缺失时旧包继续可用。Windows目标机器上的文件替换／备份行为必须实测，不仅依赖内存事务。

v0.2测试写入新的工作目录和 `user://tests/v02/` 或独立的v0.2运行配置；不覆写 `authoring/workspace.json`、旧发布、旧 `_03` 和修复版 `_02` 发行包。新目录名单通过仓库允许列表检查后才能进入提交。

## 15. 性能与正确性测试规范

### 15.1 分三类测，不能混在一起

**A/B基线测试：** 旧画风、相同内容、相同机器和实际分辨率，对比旧与新显示链；不混入美术变化。  
**目标视觉测试：** 新小样、正常游戏状态与真实缩放，测玩家将看到的负载。  
**规模／故障夹具：** 合成大目录、唯一资源、低预算、延迟、缺页与快速镜头；范围单列，不冒称历史地图。

### 15.2 计时和环境

发布构建，固定Godot4.6.1与Compatibility基线；记录完整CPU/GPU/驱动/RAM、项目设置、桌面DPI、窗口客户端尺寸、实际Viewport纹理尺寸与内容缩放。

目标1080p测试以实际1920×1080渲染缓冲为准，不仅看project.godot。其他尺寸也保留结果，但不能改名为1080p。截图读回不放入性能采样循环。

单调时钟记录进程开始、首个可交互低清画面、所需细页准备、提交与展示阶段。无法可靠观测的外部时点标记null／upper_bound，日志被读到的时间不伪装成GPU首帧时间。

首次进程运行与重复运行分别标注；不默认等于清空OS磁盘缓存后的冷启动，也不擅自结束用户其他程序。

### 15.3 正常负载目标

固定轨迹60秒运行3次，另一次300秒耐久。稳态p95≤16.7ms、p99≤25ms；记录每次结果与最差一次，不能只报最好一轮。先沿用目标机器，再按需要增加第二台设备，不从“主流配置”推导保证。

长帧另外报告：>33／50／100ms计数、最大帧、发生镜头和是否伴随挂接。正常平移中可归因于地图的重复>50ms尖峰必须处理；单个外部抖动仍保存证据，不能删样。瞬移首次补细节单列时延，但代理及输入必须持续可用。

### 15.4 空间查询验收

对同一可见对象集增加大量离屏对象，比较query、排序、绘制计划和资源加载成本。记录 `world_records / resident_records / buckets_visited / candidates_tested / visible_objects / submitted_objects / sort_rebuilds`。

不声称复杂度绝对O(1)。目标是工作量主要随访问桶和候选数增长；10万条离屏对象不应在每帧被逐条扫描。测试时用全量参考算法对照结果集合，确保优化不漏树冠或错丢跨界对象。

### 15.5 真正的流式往返

在多个不相邻区域间往返至少20轮，路线覆盖的唯一资源量超过软预算3倍。记录每页的request、attach、last_reference_drop与reload事件。

必须观察到不同内容离开驻留集合、释放引用、之后重新载入；只开关界面或者隐藏节点不算。回到同一视野并等待相同稳定期，比较内存窗口和引用集合，检查长期趋势；不要求驱动内存逐字节相等。

### 15.6 失败注入

单页文件缺失、错误哈希、读取延迟、快速瞬移、半途切换世界／包、内存预算缩小、跨块超大树、父页未就绪、旧候选过期、构建中断、保存恢复与风格迁移拒绝。

每种错误都写清：保持什么旧状态、显示什么回退、是否允许重试、结果是不是失败。UI不中断不代表测试通过；错误被正确报告和隔离才是故障用例的通过条件。

## 19. 完成定义与下一阶段门槛

v0.2完成必须同时满足：

**视觉关卡：** 作者明确接受一个引擎内手绘组合样板及原位状态变化。  
**工程关卡：** 同一世界按视野加载、释放、重入，候选查询与绘制不遍历全量细节，过期请求和缺页行为正确。  
**兼容保护关卡：** 已有ID、v4、Save22、补丁、删除记录和锁区不被改写，旧发行可回退。  
**性能关卡：** 实际目标分辨率的必测profile达到冻结预算，原始数据可复查，未达的探索规模明确列出。

精确756历史复原不作为本版已完成声明；既有候选和不确定性仍保留。全东亚近景资源量与城市数尚未定量，不能给全国容量保证。

只有上述门槛全部达成，再设计v0.3：第二种真实地理节点＋地区级内容生产。第二节点应验证不同地理条件，而不是复制潼关改名。这个安排不是本文件自动授权开始制作该节点。
