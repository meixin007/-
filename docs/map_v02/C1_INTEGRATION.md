# C1 地形、城镇与流式地图整合

本批新增 `runtime/v02/c1`，复用冻结的 E1 协议和解析器、E2 空间索引与增量绘制计划、E3 异步后端和预算／释放状态机。C1 服务和渲染器继承 E3；覆盖规划仅扩展纹理 LOD 迟滞，绘制层仅扩展城镇语义、标签、工程势力覆盖及淘汰时的局部过渡失效。

真实潼关与 256 页／256 工程地点夹具使用同一入口和加载流程。唯一 Session 直接沿用 V2 的原 FinalController／SettlementState，创建唯一 GameState／Context；启动阶段不初始化旧六块地形缓存。原默认项目、旧地图、源美术、原 V1／V2／R1／E1—E3 源码与收据保持不变。

## 表现输入与权威

不可变地形仅将 R1 既有地面和水层确定性合成到新构建目录；原 PNG 不修改。保持 12 个 512m 细页、1024px core、32px gutter、线性基础层采样和原 24×16km 概览。全部树、仓库、驻军院落、墙段、军队、文字和势力覆盖保留运行时显示，没有烘入地面。完整参考纹理只用于 GPU 验证，交互入口不持有它。

E1 的 `visual_review.json` 仍仅证明原 V1 风格通过；独立 `terrain_review.json` 明确 R1／V2／C1 组合候选待审阅。作者“好很多”记录为地形正面反馈，不替代整合版视觉签署。

城市适配读取原 `site_id + slot_id + building_type + construction_state + damage_level`。只在原状态修订／epoch／实例变化时取得投影，更新 E2 中对应的三个对象；真实建筑 ID 另保存在记录中。地块、接地点、关楼、墙接点、道路和生成器不变。E3 需求映射更新到当前资产，未加载完成时保留地点代理。

存档通过原 Save22 加载流程。C1 校核当前有效制作内容与包内同源摘要；不匹配则明确拒绝候选显示并保留原状态，不自动替换存档中的制作内容。

## 远近景与生命周期

语义 LOD 使用固定布局参考宽 1200m 的屏幕投影，32／128／384px 阈值，15% 迟滞。依次为图标、剪影、简化布局、详细院落。简化与详细复用相同建筑骨架／资产／锚点，详细档加入原静态树和 13 个已接受的 V1 审阅摆放，标识为 `v1.preview.*`。代理在可见详细资产全部就绪后经过 180ms 过渡退出。

纹理 LOD 单独使用 E3 的页密度判据，并加 15% 迟滞。先与发布范围求交，再查询覆盖桶，远景不遍历整片东亚的空细页。父子过渡保留同构建父覆盖，概览只提交一次。

卸载先清绘制命令及节点引用，再清 E3 需求，继续排空真实异步请求；原时钟／施工状态不因此改变。重载从原权威投影和当前修订重建可见计划。可在卸载期间通过原合同支付 120 钱、20 木并推进三天完成仓库，再损毁、重载和修复。

标签先按视野筛选，再按选中地点／行动目标／重要性排序并做屏幕避让，上限 64；选中地点另在侧栏回执。东亚沿用原粗示意底图；工程势力为两个共享边界的示意区域，颜色切换只更新覆盖层，不重烘地形。工程夹具不新增真实城镇或历史疆界。

## 检查与审阅边界

独立新目录构建 `tools/map_v02/c1_build.py`，原生检查 `c1_native.py`，兼容回归 `c1_regressions.py`，封存 `c1_finalize.py`。原生证据包括全尺度往返、每个语义阈值和实际纹理阈值的 20 次往返、父子混合、真实纹理弱引用释放、五次卸载重载、离屏施工、损毁／修复、同加载器工程夹具、标签避让、势力颜色零地形重建、低预算回退及实际导入像素哈希。

七组分页／整幅 GPU 对照使用测试前冻结的最大通道差 1，并用 40m 错位作为应检出的反向对照。原位修复和稳定机位卸载重载继续要求地图像素完全相同。

本批为 C1 功能整合候选，视觉待作者审阅。历史准确性、深 mip、Q1 的 3×60 秒与 300 秒完整帧时／显存／容量签署分开处理。保留正常 256／320MiB 配置与明确标注的 32／48MiB 压力配置，不把压力降级结果当成 Q1 正常档验收。
